本篇对应原书第 26 和第 27 章。

虚拟化讨论的是如何让多个程序共享 CPU 和内存。并发讨论的是另一个更麻烦的问题：多个执行流同时推进时，如何保证结果正确。

并发程序最让人不舒服的地方在于，它们经常不是每次都错。今天跑一百次没问题，明天换个负载、换台机器、加一行日志，问题就出现了。

## 并发错误为什么难复现

单线程程序通常有一条明确的执行路径。只要输入一样，结果大概率一样。

并发程序多了一个隐藏输入：调度顺序。

同一段代码、同一组输入，在不同线程交错下可能得到不同结果。调度顺序又受 CPU 数量、中断时机、I/O、系统负载和编译优化影响，所以很多 bug 不会稳定复现。

## 线程和进程的区别

进程拥有独立地址空间。线程属于同一个进程，多个线程共享代码、堆和全局数据，但每个线程有自己的栈和寄存器上下文。

这带来两个后果：

- 线程之间通信方便，因为它们天然共享内存。
- 线程之间互相破坏也方便，因为共享状态需要显式同步。

并发问题大多不是因为“有多个线程”，而是因为多个线程访问了共享状态，并且至少有一个线程在写。

如果多个线程只读共享数据，通常比较安全。如果每个线程只写自己的私有数据，也比较安全。真正危险的是共享可变状态。

## 共享计数器为什么会错

看似简单的代码：

```c
counter++;
```

并不一定是一个原子操作。它可能被编译成类似这样的步骤：

1. 从内存读取 `counter` 到寄存器。
2. 寄存器里的值加一。
3. 把结果写回内存。

如果两个线程交错执行这三步，就可能丢失一次更新。

这就是并发学习里最重要的直觉：不要相信源代码里的“一行”。要想象它在机器层面可能被拆成多条指令，而调度器可以在很多位置切换线程。

可以把两个线程想成这样交错：

| 步骤 | 线程 A | 线程 B |
| --- | --- | --- |
| 1 | 读到 counter = 0 |  |
| 2 |  | 读到 counter = 0 |
| 3 | 计算得到 1 |  |
| 4 |  | 计算得到 1 |
| 5 | 写回 1 |  |
| 6 |  | 写回 1 |

两个线程都执行了一次加一，最终结果却只增加了 1。

## 关键术语

| 概念 | 含义 |
| --- | --- |
| 临界区 | 访问共享资源的一段代码 |
| 竞态条件 | 结果依赖线程执行时序 |
| 不确定性 | 每次运行可能出现不同交错 |
| 互斥 | 同一时间只允许一个线程进入临界区 |
| 原子性 | 一组操作不可被中途观察或打断 |

这些词不是定义游戏。它们对应真实代码里的判断。

只要你看到多个线程读写同一个变量、队列、链表、缓存或文件状态，就要问：这里有没有临界区？有没有竞态？需要互斥还是需要等待某个条件？

## 并发不是只需要互斥

很多人第一次学并发，会把所有问题都理解成“加锁”。

但并发至少有两类问题：

第一类是互斥。多个线程不能同时修改同一个共享结构。

第二类是等待。一个线程必须等另一个线程把状态准备好，例如父线程等待子线程结束，消费者等待缓冲区非空，生产者等待缓冲区非满。

锁主要解决第一类问题。条件变量、信号量等同步原语会解决第二类问题。

这也是很多并发代码变乱的原因：本来需要表达等待条件，却只用锁硬撑；或者本来只需要保护临界区，却引入复杂通知机制。

## 线程 API 的基本形状

线程 API 通常提供几类能力：

- 创建线程：指定新线程从哪个函数开始运行。
- 等待线程：等待线程结束并取得返回值。
- 同步线程：用锁、条件变量等保护共享状态。

创建线程本身不难。难的是决定哪些状态可以共享、由谁修改、什么时候其他线程可以看到。

## 学习并发时的检查清单

看到一段并发代码，可以按下面的问题检查：

1. 哪些数据是共享的？
2. 哪些路径会写这些数据？
3. 读写是否可能同时发生？
4. 哪些操作必须作为一个整体？
5. 如果线程在任意两条机器指令之间被切走，结果还正确吗？

这比只问“有没有加锁”更可靠。

## 常见误区

**误区一：加锁后就一定正确。**

锁只保证互斥，不保证锁住的范围正确，也不保证等待条件正确。锁太小可能保护不住不变量，锁太大可能导致性能下降甚至死锁。

**误区二：测试通过就说明没有竞态。**

竞态依赖调度顺序。测试只是覆盖了一些交错，不代表覆盖了所有交错。

**误区三：volatile 能解决并发问题。**

`volatile` 不能把复合操作变成原子操作，也不能替代锁和同步原语。

## 复盘问题

1. 线程共享哪些进程资源，又有哪些状态是线程私有的？
2. 为什么 `counter++` 不是可靠的原子操作？
3. 互斥和等待条件分别解决哪类问题？
4. 为什么并发 bug 经常和机器负载、CPU 数量有关？

## 小结

并发的根源是共享状态和不可预测调度。

线程让程序更容易利用多核，也更容易把状态暴露给多个执行流。理解并发的第一步，就是把“源代码顺序”拆成“可能交错的执行步骤”。只有这样，后面的锁、条件变量和信号量才不会变成孤立语法。
