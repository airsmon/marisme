本篇对应原书第 7 到第 10 章。

进程让多个程序可以共享 CPU。接下来的问题是：多个进程都 ready 时，操作系统应该运行谁？

这就是 CPU 调度。

调度不是简单地挑一个进程。它真正面对的是目标冲突：周转时间、响应时间、公平性、吞吐量、缓存亲和度，通常不能同时最优。

## 先给调度定一个边界

调度器只在某些时刻做决定。比如进程创建、进程退出、进程阻塞、I/O 完成、时间片用完、时钟中断到来。

所以调度算法不是每个纳秒都重新思考一次，而是在系统状态发生变化时，从 ready 队列里选一个接下来运行的对象。

理解这个边界很重要。否则很容易把调度想成一个全知、连续、完美的决策器。真实调度器面对的是不完整信息和有限开销。

## 先看两个指标

调度算法讨论最多的两个指标是：

- **周转时间**：任务从到达到完成用了多久。
- **响应时间**：任务从到达到第一次运行用了多久。

批处理系统更关心周转时间，交互式系统更关心响应时间。

这两个目标经常冲突。一个算法可能让平均完成时间很好，但让用户等很久才看到响应。另一个算法可能响应很快，但频繁切换导致整体效率下降。

可以用一个很小的场景感受差异：一个长任务先到，两个短任务随后到。如果坚持 FIFO，短任务会被长任务挡住；如果优先短任务，平均周转时间会好很多；如果使用轮转，短任务能更快开始响应，但长任务和短任务之间会不断切换。

## FIFO：简单但容易护航

FIFO 就是谁先来谁先运行。

它的优点是简单，容易实现。问题是如果一个长任务先到，后面很多短任务都要等它跑完，这就是护航效应。

所以 FIFO 适合做理解起点，但不是通用好策略。

## SJF 与 STCF：短任务优先

SJF 选择最短任务优先。在任务都同时到达且运行时间已知时，它能优化平均周转时间。

STCF 是抢占式版本。如果新来的任务剩余时间更短，就抢占当前任务。

问题在于，操作系统通常不知道任务未来会运行多久。这让理论最优和真实系统之间出现差距。

## 轮转：改善响应

轮转调度让每个 ready 进程运行一个时间片，然后切到下一个进程。

它改善了响应时间。交互任务不用等前面的长任务全部跑完，就能较快获得 CPU。

但时间片大小很关键：

- 太大，接近 FIFO，响应差。
- 太小，上下文切换过于频繁，开销高。

所以调度从一开始就是折中。

## MLFQ：从历史中学习

多级反馈队列试图在不知道未来的情况下，根据过去行为猜测任务类型。

大致规则是：

- 高优先级队列先运行。
- 同一优先级内轮转。
- 新任务进入高优先级队列。
- 用完整个时间片的任务降低优先级。
- 经常主动让出 CPU 的任务保持较高优先级。
- 周期性提升优先级，避免饥饿。

这个策略对交互型任务友好。交互型任务通常运行一小会儿就等待 I/O，MLFQ 会倾向于让它保持较高优先级。CPU 密集型任务会逐渐下沉，但仍然能继续前进。

MLFQ 的难点在参数。队列数量、时间片长度、提升周期都会影响行为。

MLFQ 的关键不是“有很多队列”，而是它承认系统不知道未来，只能从过去行为里猜。

如果一个任务总是很快让出 CPU，它可能是交互型任务，应该获得较快响应。如果一个任务每次都用完整个时间片，它更像 CPU 密集型任务，可以降低优先级，让其他任务先获得机会。

## 比例份额调度

有时目标不是响应速度，而是资源占比。

彩票调度用票数表达 CPU 份额。进程拥有的彩票越多，越可能被抽中运行。

它的好处是简单、灵活、状态少。缺点是短时间内可能不稳定，因为随机性需要足够长的时间才接近期望比例。

步长调度则提供更确定的比例份额效果。它用 stride 和 pass 值记录每个任务应得的推进程度，让调度结果更可预测。

## 多处理器调度的新问题

单 CPU 调度只问“运行谁”。多 CPU 调度还要问“在哪个 CPU 上运行”。

这会带来新问题：

- 多个 CPU 访问同一个运行队列，需要同步。
- 进程回到之前的 CPU，可能复用缓存内容。
- 每个 CPU 一个队列时，可能出现负载不均。

单队列简单，但竞争严重。多队列扩展性好，但需要迁移任务来平衡负载。

这里还有一个容易忽略的点：调度不只影响“什么时候运行”，还影响缓存命中率。

一个进程刚在某个 CPU 上运行过，相关数据可能还在该 CPU 的缓存里。如果下一次仍然在同一个 CPU 上运行，就可能更快。这就是缓存亲和度。多处理器调度不仅要公平，也要尽量少破坏局部性。

## 常见误区

**误区一：公平就是每个任务完全一样。**

有时公平是相同 CPU 时间，有时是按权重分配，有时是保证交互任务不被饿死。不同系统对公平的定义并不一样。

**误区二：时间片越小响应越好。**

时间片太小会增加上下文切换开销。响应性和开销之间要平衡。

**误区三：调度算法能弥补所有负载问题。**

如果系统过载，调度只能决定谁先受影响，不能凭空创造 CPU。

## 小结

调度算法没有绝对最好。看到一个调度策略时，先问它优化什么，再问它牺牲什么。

| 策略 | 强项 | 主要问题 |
| --- | --- | --- |
| FIFO | 简单 | 护航效应 |
| SJF / STCF | 周转时间好 | 需要知道运行时间 |
| Round Robin | 响应时间好 | 时间片和切换开销难平衡 |
| MLFQ | 适合交互系统 | 参数复杂，行为依赖历史 |
| Lottery | 表达比例份额 | 短期不稳定 |

调度这件事最有价值的地方，不是记住每个算法，而是理解系统设计里无法逃开的取舍。
