本篇对应原书第 28 到第 31 章。

并发程序需要同步。同步原语很多，但最常用的还是这三类：

- 锁
- 条件变量
- 信号量

它们不是同一个东西的三种写法。每一种原语适合表达的问题不同。

## 先分清两个需求

同步问题可以先粗略分成两类：

1. **互斥**：不要让多个线程同时进入某段代码。
2. **等待**：条件还没满足时，让线程先停下来，等别人改变状态。

锁主要解决互斥。条件变量主要解决等待。信号量既能做互斥，也能做计数和通知，但越灵活越需要克制。

只要先把需求分清，后面的 API 就不容易混。

## 锁解决互斥

锁的目标很直接：同一时间只允许一个线程进入临界区。

如果多个线程会修改同一个共享结构，就需要用锁保护这个结构的不变量。

一个锁实现至少要考虑三点：

- 正确性：是否真的互斥。
- 公平性：等待线程是否可能长期拿不到锁。
- 性能：等待时是自旋、让出 CPU，还是睡眠。

简单自旋锁在多核且临界区极短时可能有效。但如果锁持有时间较长，自旋就是浪费 CPU。

评价一把锁时，不能只问它是否正确，还要问等待线程怎么等。如果等待线程一直占着 CPU 循环检查，就是自旋。如果它让出 CPU 或睡眠，调度器就能把 CPU 给其他工作。

## 锁需要硬件原子指令

锁本身也要被多个线程同时访问，所以实现锁需要更底层的原子能力。

常见硬件原子指令包括：

- test-and-set
- compare-and-swap
- load-linked / store-conditional
- fetch-and-add

它们提供很小但足够坚硬的原子基础。操作系统和线程库在这个基础上构建更完整的锁。

## 条件变量解决等待

锁只解决“谁能进入临界区”，不能优雅地解决“条件不满足时怎么办”。

例如消费者发现缓冲区为空，它不应该一直占着 CPU 反复检查，而应该睡眠，等生产者放入数据后再被唤醒。

这就是条件变量的用途。

条件变量有几条重要规则：

- 等待条件前必须持有相关锁。
- `wait` 会原子地释放锁并让线程睡眠。
- 被唤醒后线程会重新获得锁。
- 检查条件要用 `while`，不要用 `if`。

最后一条尤其重要。线程被唤醒，不代表条件一定仍然成立。可能有虚假唤醒，也可能有其他线程先一步修改了状态。

条件变量的正确心智模型是：

```c
pthread_mutex_lock(&lock);
while (!condition) {
    pthread_cond_wait(&cond, &lock);
}
// condition is true, operate on shared state
pthread_mutex_unlock(&lock);
```

这里的 `while` 不是保守写法，而是语义的一部分。线程醒来后必须重新检查共享状态。

## 生产者消费者问题

有界缓冲区是理解条件变量的经典例子。

- 生产者在缓冲区满时等待。
- 消费者在缓冲区空时等待。
- 缓冲区状态由锁保护。
- 通常需要两个条件变量：`not_full` 和 `not_empty`。

这里的重点是：条件变量不是用来“发消息”的，而是用来等待某个受锁保护的状态变为真。

在这个模型里，锁保护缓冲区本身，条件变量表达缓冲区状态：

- `not_empty`：消费者等待“有数据可取”。
- `not_full`：生产者等待“有空间可放”。

如果只用一个条件变量，生产者可能唤醒另一个生产者，消费者也可能唤醒另一个消费者。两个条件变量能把等待原因分开，代码更清楚。

## 信号量

信号量是一个带整数值的同步对象。`wait` 尝试减一，不能减时等待；`post` 加一，并可能唤醒等待者。

信号量可以表达多种场景：

| 场景 | 用法 |
| --- | --- |
| 互斥 | 初始值为 1 的二值信号量 |
| 一次性通知 | 初始值为 0，完成后 post |
| 资源计数 | 初始值为资源数量 |
| 有界缓冲区 | empty 和 full 分别表示空槽和数据数量 |

信号量很强大，但也容易让代码意图变模糊。能用锁和条件变量清楚表达时，通常更容易维护。

## 怎么选

可以先按问题类型选：

| 问题 | 优先选择 |
| --- | --- |
| 保护共享数据结构 | 锁 |
| 等某个状态变为真 | 条件变量加锁 |
| 管理固定数量资源 | 计数信号量 |
| 简单的一次性完成通知 | 信号量或条件变量 |
| 极短临界区、多核低竞争 | 自旋锁可考虑 |

不要为了炫技混用原语。同步代码越清楚，后续越容易证明它是正确的。

## 常见误区

**误区一：条件变量可以不配锁。**

条件变量等待的是共享状态，锁负责保护这个状态。如果没有锁，检查条件和进入等待之间会有竞态。

**误区二：`signal` 就等于条件成立。**

`signal` 只表示“可能发生了变化”。被唤醒线程必须重新检查条件。

**误区三：信号量更通用，所以应该优先用信号量。**

通用不等于清晰。信号量适合资源计数和某些经典同步问题，但复杂业务状态通常用锁加条件变量更容易读。

## 小结

锁、条件变量和信号量分别解决不同层次的问题。

锁保护临界区。条件变量表达等待条件。信号量用整数计数把资源、通知和互斥都统一起来。

真正写并发代码时，先把共享状态和等待条件说清楚，再选择原语。反过来先选原语，往往会把程序写得越来越难理解。
